## 1. 门禁原则

每个阶段只回答一个问题。当前阶段没有证据时，不进入下一阶段。

```text
输入完整 -> 仓库一致 -> 计划有界 -> 根因明确 -> 修改最小
-> 验证通过 -> 审查完成 -> 提交完成 -> 结果包完整
```

任务单没有写出的实现风格偏好，选择仓库里已有且影响最小的做法。该规则不适用于
字段、路径、验证命令、验收条件或权限；这些内容缺失时必须停止。

## 2. 阶段门禁

| 阶段 | 进入条件 | 必须留下证据 | 失败动作 |
| --- | --- | --- | --- |
| 输入 | 任务单可读 | 8 个章节、必需字段和占位符检查完成 | `BLOCKED` |
| 仓库 | 路径和分支存在 | 当前提交、工作区、索引和未跟踪文件清单 | 停止 |
| 计划 | 目标模块已定位 | 不超过 5 步的书面计划 | 继续只读调查 |
| 实现 | 根因或设计边界清楚 | 修改路径和理由 | 回到调查 |
| 验证 | 实现完成 | 完整命令、退出码、关键输出 | 修复；停止时按代码提交状态判定 |
| 审查 | 验证通过 | diff 检查和需求逐项核对 | 修复后重验 |
| 提交 | 审查完成 | 提交 SHA、文件清单 | 不提交 |
| 回传 | 尝试写入输出目录 | 与状态匹配的结果文件或最终回复 | 已提交用 `PARTIAL`，未提交用 `BLOCKED` |

## 3. Git 安全

- 修改前运行 `git status --short`、`git diff --cached --name-only`、
  `git ls-files --others --exclude-standard` 和 `git rev-parse HEAD`。
- 任务单要求的分支与实际分支不一致时停止。
- 索引必须为空。已存在的未提交修改或未跟踪文件默认属于用户；与允许修改路径重叠时
  停止。
- 不得执行 `git reset --hard`、`git clean -fd`、`git checkout -- <path>`、
  `git restore <path>` 或强制推送。
- 不得自动解决 merge/rebase 冲突。
- 只按显式路径暂存。提交前运行 `git diff --cached --name-only` 和
  `git diff --cached --check`。暂存清单出现无关文件时停止，不执行提交。
- 提交后重新运行 `git status --short`、`git ls-files --others --exclude-standard` 和
  `git show --stat --oneline <result_commit>`。本任务新建文件仍在未跟踪清单中时，
  不得标记 `DONE`。
- 提交失败时保留修改，报告失败原因并使用 `BLOCKED`，不得声称已提交。

## 4. 模块边界

- 主入口、控制器、路由和调度器只负责连接现有模块。
- 解析、转换、校验、适配、持久化、输出格式和业务规则分别放在职责单一的模块。
- 新功能至少检查：是否已有同类抽象、是否可扩展现有接口、是否需要新模块、测试应放
  在哪里。
- 不以文件数量或代码行数作为唯一拆分标准。独立变化原因、独立测试需求和清晰责任
  是主要标准。
- 替换旧流程时删除旧入口、旧参数、旧分支和失效测试；未获授权兼容时不得保留双轨。

## 5. 低能力模型约束

- 一次只处理一个文件组和一个根因，避免同时进行多项重构。
- 不依赖隐含上下文。每个结论引用精确文件路径、符号、命令行输出或任务单字段。
- 不写“应该可以”“大概率”“看起来正常”。没有新鲜证据就写 `PARTIAL` 或
  `BLOCKED`。
- 不进行开放式头脑风暴。计划达到 5 步仍未收敛时停止并报告缺失信息。
- 同一错误连续出现 3 次时停止。保留最后两次命令和完整错误文本。
- 不在失败后扩大范围。不得通过增加宽泛包含目录、关闭检查、捕获所有异常或跳过测试
  来掩饰根因。
- 不信任自己的记忆。重新读取修改后的文件，核对关键声明、调用方和测试。
- 本地项目文档与源码冲突时，以源码为准并记录差异；不得修改本地只读目录。

## 6. 失败升级

按以下顺序升级：

1. 缺少输入：`BLOCKED`，列出缺失字段。
2. 环境缺失：`BLOCKED`，给出探测命令和观察结果。
3. 构建失败：保留第一条根因错误，修复后重跑同一命令。
4. 测试失败：确认失败属于本任务、既有基线还是环境问题。
5. 三次修复失败：停止，列出假设、证据和已尝试修改。
6. 部分验收通过：代码修改已全部提交时使用 `PARTIAL`；存在未提交代码时使用
   `BLOCKED`，逐项列出通过和未通过条件。

任何升级都不得删除失败日志或改写历史结果。

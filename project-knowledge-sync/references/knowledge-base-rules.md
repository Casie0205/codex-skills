## 1. 来源层级

从高到低：

1. 云电脑当前源码和可复现运行结果；
2. 云电脑审查回复中的路径、符号、行号和代码片段；
3. 用户明确确认的项目事实；
4. 本地综合框架文档；
5. 基于接口和通用原理的推断。

低层级来源不能覆盖高层级证据。源码版本不一致时，先确认分支和提交。
本地截图和旧文档可以形成 `confirmed-local`，但不能代替 `confirmed-cloud`。

## 2. 权威位置

- 每个事实只保留一个权威章节。
- 总览文档负责系统和数据流，不复制专项文档全部细节。
- 专项 Flow 文档负责模块控制流。
- 数据结构文档负责字段、所有权、生命周期和不变量。
- 知识缺口文档负责尚未回答问题。
- 原始审查记录只保存证据，不承担综合说明。

修改前先读取索引和目标文档目录。新增内容优先进入现有主题，只有独立读者目标或独立
生命周期才拆成新文档。

## 3. 伪代码规则

伪代码用于减少阅读源码成本，但不能成为新的猜测来源。

必须：

- 使用真实函数名、类型名、宏名和字段名；
- 保留入口、条件方向、循环层级、返回和清理顺序；
- 标注 `extracted` 或 `inferred`；
- 附源码路径和符号；
- 在推断处写明缺少的证据。

禁止：

- 合并多个重载或同名函数；
- 省略决定行为的条件；
- 编造参数、默认值、错误码和数学公式；
- 把设计目标写进当前流程；
- 用伪代码替代源码引用。

## 4. 文档结构

每个维护文档：

- 只有一个主要用途；
- 标题下有状态和日期；
- 目录位于首段说明之前；
- 链接所有顶层章节；
- 使用相对链接指向同项目文档；
- 不确定内容使用明确状态；
- 不留下未解释的重复章节。

大型文档达到约 8,000 字符时考虑按职责拆分，不按行数机械截断。

## 5. 索引与更新记录

合并后同步更新：

- 项目入口的文档清单和状态；
- 受影响章节的更新记录；
- 知识缺口的 `open`、`partial` 或 `closed` 状态；
- 原始审查记录的合并状态；
- 跨文档链接和旧位置指针。

索引只列出真实存在且有用的文档，不把计划中的文件写成已完成。

## 6. 云电脑可见性

本地文档可被云电脑读取，但云电脑不能写入本地。文档中必须写清：

- 哪些路径是本地只读输入；
- 哪些路径只位于云电脑；
- 云电脑结果需要用户人工带回；
- 示例路径和示例命令不得当作当前任务。

不得在本地文档中声称已经自动读取云电脑更新。
